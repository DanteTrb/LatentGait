# Software verification and limits

The package is checked using values generated entirely from scratch. No real participant table, paper-derived coefficients, fitted result targets or synthetic records calibrated from the cohort are used in tests.

```sh
python -m pip install -c constraints-tested-py310.txt -e '.[dev]'
ruff check src tests
python -m pytest
python scripts/check_code_only.py
latentgait synthetic-check --output /external/new-software-check --figures
```

The tests cover strict cohort/QC/schema checks, duplicate/blank IDs after whitespace normalization, nonfinite values, the production cohort lock, one-to-one person+trial linkage despite shuffled input, fail-closed protocol fields, and external-output paths. They also check separate domain PCA and retention strategies, fixed outcome-independent orientation and exact tie-breaking, invariance to global solver sign reversals, preservation of the kinematics anchor, aligned bootstrap intervals, scale conversion, analytic HR/iHR parity/power values, entropy against independent brute-force counts, recurrence range, restricted-cubic linear tails/continuity, tensor/numerical basis agreement and finite gradients. The shipped analysis example has complete PCA orientation; only the private QC reference and prior acknowledgement need resolving before protocol validation.

Bayesian graph tests compile finite initial log densities for all outcome forms, verify the free log-slope parameter and absence of unreported fixed-probit adjustment, check anchor residual SD through prior-predictive sampling, and compare analytic score-marginalized probit probabilities with independent numerical integration. A generated-value test verifies unchanged measurement log density under each simultaneous non-anchor PC/loading sign recoding; it is an algebraic-model check, not a claim of bitwise-identical MCMC chains. The exact-LOO control-flow test forces one problematic case, verifies that its outcome is omitted from a real model graph, and checks the replacement predictive score; it does not claim a long-chain clinical refit was run.

The explicit synthetic command executes the four measurement/association strategies, five covariate sensitivities, incremental PC2 model, three functional forms, PPC, LOO calculations, derivative/contrast reporting and speed OLS. Its 20 warm-up/20 retained draws in two chains, 8 primary/16 extended bootstrap resamples and 20 prior-curve draws intentionally exercise execution cheaply. Production uses 500 primary/5,000 extended resamples and 500 prior-curve draws. Poor R-hat, low ESS, divergences and PSIS warnings in short mode are expected and retained. All short-mode comparisons are unsuitable for inference; automatic exact LOO sampling refits are skipped.

Final-specification regression tests additionally cover shared participant resamples across domains, preservation of the first 500 draws when extending to 5,000, fixed PCA refitting, prior-only spline curves, all six derivative-region checks (70%, 80%, and 90% thresholds on 1,000- and 2,000-point grids), and the absence of odds-ratio columns for probit/spline coefficients. The primary cumulative-contrast convention for Figure S1 is now `lower_tail_90`: baseline latent-instability scores are ordered increasingly, tied scores are combined, and absolute posterior-mean contrasts are accumulated from the minimum observed score to the first score where the cumulative share reaches or exceeds 90%. The reported included-weight fraction must therefore be at least 0.90 when total contrast weight is positive. Empirical central weighted quantiles (`central_90`) remain an alternative descriptive calculation, not the primary Figure S1 rule. At the time of this documentation update, the synthetic integration assertions still need to be switched from `central_90` to `lower_tail_90`; passing end-to-end verification of the revised primary convention must not be claimed until those checks have been updated and rerun. These software checks do not establish that reconstructed conventions reproduce historical cohort numbers.

All production Bayesian fits enforce 4 chains and 3,000/3,000 iterations at .95 target acceptance. Reported adequacy requires finite rank R-hat <=1.01, bulk and tail ESS >=400, and zero divergences. BFMI is reported separately. This is a declared software diagnostic gate, not a criterion stated by the manuscript or proof of model validity. A run with weak diagnostics is recorded as complete computationally but its inference remains flagged inadequate.

CI runs installation, static checks, unit/graph tests, a complete synthetic short execution, final-protocol report validation (`scripts/check_synthetic_run.py`) and a post-run privacy scan. Integration checks cover the fixed PCA conventions, 8/16 short-mode resample counts, all six curve checks per model, the absence of OR fields from every probit export, and the absence of participant/trial ID columns in analysis CSVs. **Pending release check:** `scripts/check_synthetic_run.py` currently asserts `central_90` in the protocol metadata and aggregate-contrast summary, although `configs/analysis.example.yaml` now selects `lower_tail_90`. Both assertions must be updated, and the synthetic integration check and unit tests rerun to verify that the selected rule and included cumulative mass (>=90%, when defined) are correct. CI uploads no outputs or logs as artifacts. These checks establish software behavior; exact cohort-number agreement, clinical validation and external transportability remain unverified.
